## 🧩 通用知识点 & 概念库

刷题过程中遇到的、不太熟悉的语法 / 概念，按主题归类，后续专题里遇到新的会持续补充在这里。

### 1. 循环边界条件的判断方法

> 💡 判断 `<` 还是 `<=`，本质是问自己两个问题：

① 这个边界值对应的位置，任务需不需要它？

② 这个位置之前有没有被别的逻辑处理过（会不会重复）？

不确定时，用一个最小的具体例子（如单行/单列矩阵）手动模拟一遍，比纯推理更快找到 bug。

### 2. `matrix.length` vs `matrix[0].length`

| 表达式 | 含义 |
| --- | --- |
| `matrix.length` | 外层数组长度 → **行数** |
| `matrix[0].length` | 内层数组（第0行）长度 → **列数** |

> ⚠️ **易错点**：这两个值都是「总数」，不是下标。只有需要「最后一个合法下标」时才 `-1`（如 `matrix.length - 1` 表示最后一行下标）。是否 `-1` 取决于你打算怎么用这个数，而不是它是行还是列。建议固定命名习惯：`let n = matrix.length`（行数）、`let m = matrix[0].length`（列数），避免像 `row`/`col` 这种容易和实际含义搞反的命名。

### 3. `break` 的作用范围

`break` 只会跳出**离它最近的那一层**循环，外层循环不受影响会继续执行。如果需要同时终止多层循环，单独用 `break` 做不到，需要借助标志位（flag）或把逻辑包进函数里用 `return` 直接跳出。

### 4. 变量作用域（Scope）与「循环外声明」的时机

> 💡 判断标准：**这个变量的值需不需要跨越多轮循环被记住/更新？**

- 用 `let`/`const` 声明的变量，只在它所在的 `{}` 内存活，出了作用域就访问不到了（如 `return i` 在循环外访问循环体内声明的 `i` 会报错 `i is not defined`）。

- **累加/累积模式**：像 `result ^= n`、`sum += n`、`max = Math.max(max, n)` 这类写法，要求变量必须声明在循环**外面**并用 `let`（不能用 `const`，因为 `const` 不能重新赋值）。如果声明在循环体内部，每轮都会被重新初始化，之前累积的结果全部丢失。

```
// 常见累加器模式
let sum = 0; for (const n of nums) sum += n; // 求和
let max = -Infinity; for (const n of nums) max = Math.max(max, n); // 求最大值
let count = 0; for (const n of nums) if (条件) count++; // 计数
let result = 0; for (const n of nums) result ^= n; // 异或
```

### 5. `Set` vs `Map`：能不能解构遍历

| 结构 | 说明 |
| --- | --- |
| `Set` | 只存「单个值」，没有 key。`for (let item of set)` 每次拿到的就是那个值本身，**不能**写成 `for (let [a,b] of set)`（会报错，因为 item 不是数组，没法解构出两个变量）。
常用 API：`set.has(x)` 只能判断存在与否，**不能计数**。 |
| `Map` | 存「键值对」。`for...of` 遍历时每一项天生是 `[key, value]` 这样的二元数组，所以能用数组解构写成 `for (let [num, count] of map)`。
常用 API：`map.get(key)`（不存在返回 `undefined`）、`map.set(key, value)`（存在则覆盖）。 |

```
// 用 Map 统计出现次数的标准写法
const map = new Map();
for (let n of nums) {
map.set(n, (map.get(n) || 0) + 1);
// ^ map.get(n) 若为 undefined（没出现过），用 || 0 兜底
// 否则 undefined + 1 会得到 NaN
}
for (let [num, count] of map) { ... } // 数组解构，num=key, count=value
```

### 6. 数组解构赋值（Destructuring）

`let [a, b] = [1, 2]` 是按位置依次赋值的语法糖，等价于 `let a = arr[0]; let b = arr[1]`。同样的写法也用于交换两个变量：

```
[matrix[i][j], matrix[j][i]] = [matrix[j][i], matrix[i][j]]; // 原地交换，无需临时变量
```

### 7. 异或运算（XOR）的核心性质

- `a ^ a = 0`（任何数异或自己等于 0）

- `a ^ 0 = a`（任何数异或 0 等于自己）

- 满足交换律和结合律（顺序、分组不影响结果）

> 💡 应用：数组中「只有一个数出现一次，其余都出现两次」→ 把所有元素依次异或，成对的数字两两抵消为 0，最后剩下的就是答案。O(n) 时间、**O(1) 空间**，是「哈希表统计」解法的空间优化版。

### 8. `sort()` 与比较器契约

- `arr.sort()` 不带参数按**字符串字典序**排：`[10, 9, 1]` 会排成 `[1, 10, 9]`（按字符比 "10" < "9"）。数字排序必须带比较器：`nums.sort((a, b) => a - b)`。

- 比较器契约：返回**负数 → a 排前面**；正数 → b 排前面；0 → 顺序随意。记忆：`(a,b) => a-b` 是升序——减出来为负说明 a 小、该靠前。

- 比较器必须返回**数字**，不能返回布尔：`(a,b) => a > b` 只会产出 true/false（即 1/0），"a 该在前"的负数永远给不出，排序静默失效。

- `sort()` 是**原地修改**原数组，不是返回新数组。

- 谁有资格决定顺序？排序引擎（V8 用 TimSort）是执行者，比较器只是顾问——引擎每拿一对元素问一次"谁在前"，靠答案的传递性，只需问约 n log n 次就能排完。

### 9. 数组四端操作：`push / pop / shift / unshift`

| 操作 | 位置 / 复杂度 / 返回值 |
| --- | --- |
| `push(x)` | 尾部加，O(1)，返回新长度 |
| `pop()` | 尾部删，O(1)，返回被删元素 |
| `unshift(x)` | 头部加，O(n)，返回新长度 |
| `shift()` | 头部删，O(n)，返回被删元素 |

> 💡 记忆法：**名字即原因**——shift 是"移位"，在头部操作所有人都得挪位置，所以 O(n)；尾部操作不牵扯别人，O(1)。组合技：`nums.unshift(nums.pop())` = 数组整体向右轮转一格（LC189 的暴力一步）。

### 10. `for...of` vs `for...in`

`of` 遍历的是**值**，`in` 遍历的是**键**（对数组是字符串下标 `"0","1",...`）。口诀：**of 拿东西，in 拿名字**。

> ⚠️ **易错点**：对 `for...in` 的键做解构会拆出字符——`for (const [start, end] in intervals)` 拿到的是 `"0","1",...` 这些字符串，解构 `"0"` 得到 `start="0", end=undefined`。遍历区间数组请用 `for (const [start, end] of intervals)`（LC56）。

### 11. `at()` 与负数下标

`q.at(-1)` 取最后一个元素，`q.at(-2)` 倒数第二个，适合"看一眼队尾/栈顶"的场景。注意 `q[-1]` 不是负数下标，是访问名为 "-1" 的属性 → 得到 `undefined`，属于静默不报错家族。

### 12. `new Array(n).fill()` 与共享引用陷阱

- 建定长数组的标准姿势：`new Array(n).fill(0)`。光有 `new Array(n)` 得到的是 n 个"空洞"（map/forEach 会跳过它们），fill 之后才变成真值。

- **共享引用陷阱**：`new Array(2).fill([0,0])` 所有格子装的是**同一个数组**，改一个全跟着变。建二维数组必须每行 new 一个新的：`Array.from({length: m}, () => new Array(n).fill(0))`。

### 13. 单位元（中立元素）速查

| 运算 | "什么都不做"时的初始值 |
| --- | --- |
| 加法 / 计数 | `0`（0 + x = x） |
| 乘法 | `1`（1 × x = x）——「空积 = 1」，这就是 LC238 里 `arr = [1]`、`end = 1` 的原因：最左边元素的"左包"是空的，空乘积的值是 1 不是 0 |
| 求最大值 | `-Infinity` 或首元素（全负数数组时 0 会混进答案，LC53 用 `nums[0]` 起手） |
| 字符串拼接 | `''` |
| 收集结果 | `[]` |

### 14. 报错阅读公式（持续补充）

| 报错长相 | 翻译 |
| --- | --- |
| `X is not a function` | 把非函数的东西加了括号 / 这个方法不存在于这个类型上（如 `nums.delete()`——delete 是 Set/Map 的方法，数组没有） |
| `X is not defined` | 没声明 / 作用域不对（声明位置跟着生命周期走） |
| `[null,null,...] is not valid value for return type` | 返回数组里混进了 `undefined`/`NaN`（JSON 把它们序列化成 null）。数一下 null 的个数，能反推出 push 发生了几次、哪段逻辑多推/错推了（LC239） |

### 核心知识点

- **哈希表的本质是空间换时间**：遇到"找配对 / 问存在 / 做分组"这类需要反复查询的题，先建表把每次查询降到 O(1)，总时间 O(n²) → O(n)。代价是 O(n) 空间——这是这笔交易的价格标签，答题时要说得出来。

- **四句骨架：建表 → 遍历 → 查 → 存**。存是查的前提：边查边忘了存 = 表永远空（鸡生蛋死锁）。先写骨架再填细节。

- **LC1 题眼**：查表时 `nums[i]` 还没入表 → 结构上不可能"同元素用两次"。好代码在结构上让那类错误不可能发生，而不是靠小心。

- **LC49 题眼**：互为异位词的词排序后完全相同 → 排序后的字符串就是这组的"身份证"（key），value 装同组词数组。字符串三连招：`split('')` 拆 → `sort()` 排 → `join('')` 拼（sort 是数组方法，字符串没有，必须先拆）。

- **LC128 题眼**：O(n) 的机关是**起点资格**——`x-1` 不在 Set 里才开数；中段跳过但没丢（起点开数时会数到它），每段只数一次 → 总体 O(n)。连续 = 恰好 +1，不是"任何更大的数"。

- **Map vs Set 选择规则**：只问"在不在" → Set（花名册）；查到还要拿附加信息（下标、分组）→ Map（储物柜）。`new Set(数组)` 一步建表+自动去重；`new Map()` 构造要键值对数组，塞普通数组会报错。Map/Set 没有方括号下标。

- **打擂台**：`max = Math.max(max, 挑战者)`——擂主永远在第一个参数，max 声明在循环外（全程一本账），破纪录才更新。

### 通用技巧

| 技巧 | 说明 |
| --- | --- |
| 变量生命周期自检 | 声明任何容器/指针前自问：**"每轮都要新的，还是全程只要一个？"**全程一个放循环外，每轮新的放循环内。LC1 把 Map 建在循环里 = 每轮重建、永远是空表。 |
| 循环选型 | 循环体里用得到下标 → 传统 `for (let i...)`；只要元素 → `for (const x of 集合)`。默认先试 for...of，少一个变量少一类错。 |
| 配对问题内层起点 | 暴力枚举配对时内层从 `j = i + 1` 开始，天然避免"自己匹配自己"，还省一半重复比较。 |
| Map 交答案的三出口 | `keys()` 拿凭条 / `values()` 取包 / `entries()` 连包带凭条，都要套 `[...]` 转数组。直接 `[...map]` 等价 entries，会把 key 也带出来。 |
| 主动构造极端用例 | 重复值（`[3,3]`）、单元素、空——主动构造自测，不等判题器告诉你。Case 过了不代表对，可能只是恰好绕过了陷阱（幸存者偏差）。 |
| 哈希表识别信号 | 新题先问"这题反复要回答的问题是什么"：谁之前见过吗 → Map；它在不在 → Set；属于哪一组 → Map。附带信号：要求 O(n)、数组未排序、需要快速查找。 |

### 本专题踩过的坑

> ⚠️ LC1 暴力版：内层 `j` 从 0 开始扫全数组，`[3,3], target=6` 时返回 `[0,0]`——同一个元素用了两次；Case1 能通过纯属运气，恰好绕过了"自己匹配自己"的陷阱。

> ⚠️ LC1 哈希版两连坑：① `const map = new Map()` 写进循环里，每轮重建永远空表；② 只写 `map.has(need)` 忘了 `map.set`，光查不存。还写过 `map.set(map)` 不知道括号里填什么——写 set 前先想两问：以后拿什么查（= key）？查到想要什么（= value）？

> ⚠️ LC49：`if (map.has(key)) return`——逻辑反了 + return 误用：key 存在说明组已建好，正该 `get` 出来 `push` 入伙；`return` 是整个函数交卷走人，"跳过本轮"要用 `continue`。

> ⚠️ LC49：`map.set(map(str), key)` → `TypeError: map is not a function`（报错公式：X is not a function = 非函数被加了括号），且 set 参数顺序反了——`set(key, value)` 凭条永远在前。

> ⚠️ LC49：`return [...map]` 展开错对象——直接展开 Map 拿到的是键值对，身份证也被带出来了；题目要分组结果，应 `[...map.values()]`。

> ⚠️ LC49：`str.split(strs)` 括号里填错——split 括号填**分隔符**（怎么切），点号前才是被切对象（切谁），逐字母切开是 `str.split('')`。链式调用 = 流水线：每个方法吐出结果进下一步，整条链赋值给 key 是因为后面要用三次（has / get / set）。

> ⚠️ LC128：边遍历边查空表 → 鸡生蛋死锁（has 永远 false → 永远走不到 set → 表永远空）。**先建满表，再开始问问题**：`new Set(nums)` 一句话全班登记完毕。

> ⚠️ LC128：思维停在"从表里挨个拿出来比"——哈希表不是遍历比较，是**算好要找谁，直接 has() 问**：找"比 x 小 1 的数"就是一句 `set.has(x - 1)`。

> ⚠️ LC128：`new Map(nums)` 报错——Map 构造要键值对数组，一堆孤零零的数字它不知道怎么办；这题只问"在不在"不需要 value → 该用 Set。

> ⚠️ LC128：`while (cur-1)` 把算术当条件——数字非零即真，不"问"任何事，方向也反了。while 的条件必须是提问：`while (set.has(cur + 1))`。

> ⚠️ LC128：`return cur.length`——数字没有 .length，序列长度要算：终点 − 起点 + 1。`let cur` 声明了没赋值还放错位置：起点确认后第一件事是 `let cur = x` 站上去。

### 核心知识点

- **双指针 = 用两个指针代替双重循环**。对撞型：left/right 两端往中间挤，核心问题永远只有一个——**这轮动谁？**答案由题目结构决定（谁限制当前结果就动谁）。滑动窗口：两指针同向（都只向右），right 负责扩张、left 负责在窗口"不合法"时收缩，每个元素最多进出一次 → O(n)。

- **LC11**：面积 = `(right-left) × min(两板)`，被短板锁死 → 动长板只会更小，必须**动短板**。

- **LC125**：先清洗（`/[a-z0-9]/.test(ch)` 逐字符过滤 + toLowerCase）再两头对撞。反例（return false）循环内立刻交卷；"是回文"（return true）必须比完所有对、下在循环外——early-return 风格：循环内只下能立刻确定的结论，全局结论留给循环外。

- **LC15**：排序 → 固定 i → j/k 对撞 → 三处去重（i、j、k 各一处）。去重姿势：**先移一步、再回头看**（排序后重复元素必相邻，只需和邻居比）。O(n²) 已是最优（3SUM 猜想），这套"排序 + 固定 + 对撞"可以放心背。

- **LC42**：每格水位 = `min(左最高, 右最高) − 自己`——矮墙锁死水位，和 LC11 短板原理是同一思想。已掌握预计算版（左右各扫一遍记最高墙，O(n) 空间）；O(1) 双指针版（哪边矮结算哪边）待二刷时补。当时刻意"半跳过"当种子埋着——跳过不等于放弃。

- **LC3 变长窗**：Set 花名册记窗内住户，发现重复用 `while` 边删边查缩到干净（删一个不一定干净，所以是 while 不是 if）。Map 升级版存"字符 → 下标"，left 可直接跳：`left = Math.max(left, map.get(s[right]) + 1)`（Math.max 防 left 倒退）。

- **排序决策信号灯**：✅ 要去重 / 要双指针方向感 / 只看组合不看顺序 → 排！🚫 要保留原始下标 / 要求 O(n) / 子串子数组结构（排序破坏连续性，LC3、LC438 绝不能排）→ 不能排！

### 通用技巧

| 技巧 | 说明 |
| --- | --- |
| 动谁速查 | LC11 动短板 / LC125 一起动 / LC15 看和的符号 / LC42 结算矮边——没有一题的指针移动是"随意的"，全由题目结构决定。 |
| 收缩用 while 不用 if | 窗口"脏了"只删一个不一定干净，要边删边重新查，直到条件恢复为止。 |

### 核心知识点

- **LC438 定长窗**：窗长被 p 锁死为 k，每轮固定三步——① 新字符进窗（计数器 +1）② 窗长 > k 就把左端请出去（先加后删）③ 窗长恰好 === k 才拿窗口表和目标表对表。窗口像定员公交车：上一个人，超员了从前门下一个，满员才查票。

- **计数器模式**：`obj[ch] = (obj[ch] || 0) + 1`——先查户口，再在旧值上 +1 存回；`|| 0` 是保险丝：第一次查是 undefined，而 `undefined + 1 = NaN`，NaN 一旦沾上，后面所有比较全烂掉。

- **计数表是异位词的另一张身份证**（对比 LC49 的排序字符串身份证）：建表 O(k)、比较是 O(26) 固定开销，比排序的 O(k log k) 划算——同一件事有多种"料"，选便宜的那个。

- **旗标模式（比较两张表）**：JS 里 `{a:1} === {a:1}` 是 false——`===` 比对象比的是内存地址不是内容，内容只能逐 key 核对。骨架：循环外升旗 `let same = true`（假设无罪）→ 循环内只找反例，找到就 `same = false; break` → 循环外 `if (same)` 才收。现代等价：`Object.keys(need).every(k => (win[k]||0) === need[k])`。

- **LC560 子数组枚举**：双层 for——外层定起点 i，内层 j 从 i 出发边扩边累加 `sum`，`sum === k` 就计数。机关：sum 是"每个新起点都要重开"的变量，必须声明在外层循环体内（生命周期！）。前缀和优化（问 Map "sum − k 见过几次"，和 LC1 同一思想）待补。

- **LC239 单调队列**：普通打擂台救不了滑窗最大值——窗口缩小时旧擂主被甩出，没有"亚军"信息。单调队列 = 继承顺位表：① 新元素进窗前，`while` 把队尾所有"又老又弱"（≤ 新来者）淘汰——淘汰是相对新来者而言，不是绝对最弱；② 队头过期（下标滑出窗口）用 `if` 摘除；③ `right >= k - 1` 才开始记录答案。淘汰用 while（可能连着好几个），过期用 if（队头只有一个）。

- **队列存下标不存值**：过期判断是位置判断（`deque[0] < right - k + 1`），值判断不了位置，且重复值会撞车。要用值时 `nums[deque[0]]` 现取。

- **循环起点由"逻辑在哪成立"决定**：LC239 从 right = k-1 开始记录、LC15 去重从 i > 0 开始、LC53 从 i = 1 开始——不是机械从 0。

### 通用技巧

| 技巧 | 说明 |
| --- | --- |
| 滑窗三问 | 拿到窗口题先问：① 变长还是定长？② 收缩条件是什么（脏了 while 缩 / 超员 if 删）？③ 什么时候记录答案？三个答案定了，骨架就定了。 |
| 枚举所有子数组骨架 | `for (i) { let sum = 0; for (j = i; ...) { sum += nums[j]; 检查 sum } }`——外层定起点、内层扩终点，sum 边扩边加不用重算。 |
| 单调队列代码顺序 | 淘汰队尾（while）→ 入队 → 摘过期队头（if）→ 够长度才记录（`right >= k-1`）。 |
| 容器 API 记法 | 数组：`push/pop/shift/unshift`；Set：`add/delete/has`；Map：`set/get/delete/has`。`delete` 不是数组方法。取最后一个元素用 `q.at(-1)`（概念库 #9、#11）。 |

### 本专题踩过的坑

> ⚠️ LC438：`map.length`——Map/Set 的大小属性是 `.size`；length 属于"有顺序的东西"（数组、字符串），size 属于"装东西的容器"。

### 核心知识点

- **LC53 Kadane**：`cur = Math.max(nums[i], cur + nums[i])`——负的前缀是纯负担，带着不如重开；`max` 全程打擂台。第一个有 DP 味的模式（滚动变量：只记住"到上一个位置为止"的最优）。i 从 1 开始，因为 i=0 的状态就是初始化本身（`cur = max = nums[0]`，从首元素起手还顺便解决全负数数组）。

- **LC56 合并区间**：按 start 排序 → 遍历，只和结果数组里**最后一个**区间比：`start <= last[1]` 就合并（`last[1] = Math.max(last[1], end)`），否则新开一段。排序后"可能重叠的"必然相邻，所以只需看最后一个。解构遍历：`for (const [start, end] of intervals)`。

- **LC189 轮转数组**：`k %= n` 归一化（钟表类比：转 13 格 = 转 1 格；取余是所有"循环/周期"问题的标准答案。题目只说 k 非负、没说 k ≤ n——约束要逐条读）→ 三次翻转：整体翻 → 前 k 翻 → 后 n-k 翻，O(1) 空间。

- **解构交换**：`[nums[i++], nums[j--]] = [nums[j], nums[i]]`——右边先把两个旧值打包成数组，左边再按位置拆开装回，++/-- 最后才生效，所以不会发生覆盖。

- **LC238 前后缀乘积**：答案[i] = 左包 × 右包。第一遍从左往右：`arr[i] = arr[i-1] * nums[i-1]`（左包不含自己，arr = [1] 起手——空积 = 1）；第二遍从右往左：`arr[i] = arr[i] * end; end = end * nums[i]`——**先用后更新**，顺序是命门：end 必须先当"右包"用掉，再把自己乘进去传给下一位。口诀：右包吃自己，传给下一位。自检：arr[i] 那一行不许出现 nums[i]。

- **LC41 缺失的第一个正数**：鸽巢原理——n 个位置最多装下 1..n，答案必在 [1, n+1]。Set 版：`new Set(nums)` 后依次查 1..n，第一个缺席的就是答案；全勤则 `return n + 1`。注意遍历的是**候选值 k（从 1 开始）**，不是下标 i。原地哈希版（O(1) 空间）待补。

- **单位元意识**：乘法的"什么都没有"是 1 不是 0——LC238 的 `arr=[1]`、`end=1` 都是这个原因。完整对照表见概念库 #13。

### 通用技巧

| 技巧 | 说明 |
| --- | --- |
| 循环起点原则 | 循环从哪开始由"逻辑在哪成立"决定：LC53 从 i=1（i=0 是初始化）、LC15 去重要 i>0、LC239 从 right=k-1 才记录。不是机械从 0 开始。 |
| 极端用例自测 | 全勤（`[1,2,3,4]`→5）、单元素（`[1]`→2）、全负数——普通用例对边界 bug 是盲的。LC41 两个 off-by-one 互相掩盖，全勤用例一测就现形。 |
| 约束逐条阅读 | 约束告诉你判题器会拿什么整你：LC189 "k 非负"意味着可能 k>n（所以要 %=）；LC41 "要求 O(n)"意味着不能 sort。动手前把约束抄下来。 |

| 合并区间的"最后一个" | 结果数组的最后一个元素用 `result[result.length-1]` 或 `result.at(-1)` 取；排过序后只需和它比，不用回头扫全部。 |

### 核心知识点

- 矩阵题的空间优化，常见思路是「复用矩阵自身的某一部分（如第一行/第一列）当标记位」，避免额外开数组。

- 矩阵置零（73）的「裁决表」模式：用两个一维数组 `rowArr`/`colArr` 当判决书（0/1 即 false/true），第一遍扫描**只做记录**，第二遍才统一执行置零——绝不边扫描边置零，否则 0 会传染、污染还没读到的区域。扫描的和判决的必须分开。

- 螺旋 / 边界收缩类问题的通用范式：维护 `left/right/top/bottom` 四个边界，每走完一条边就收缩对应边界；需要 `while(left<=right && top<=bottom)` 包住整体，并对「下边」「左边」两步做重复访问保护。

- 方阵原地旋转 90°：**转置（沿主对角线互换）+ 每行翻转**，转置时只处理 `j > i` 的部分，避免换了又换回去。

- 有序矩阵搜索：利用「行列均有序」的性质，从右上角（或左下角）出发单调移动指针，将 O(mn) 降为 O(m+n)。

- 只出现一次的数字：哈希计数解法 O(n) 空间 vs 异或解法 O(1) 空间，是同一问题的两种复杂度权衡。

| 命名规范 | 行数/列数固定用 `n`（行）/ `m`（列），避免 `row`/`col` 这种容易和实际含义搞反的命名。 |

### 本专题踩过的坑

> ⚠️ 螺旋矩阵：内层循环下标行列写反（`matrix[right][i]` vs `matrix[i][right]`）；循环变量忘记自增/自减，导致重复 push 同一位置；进入新一圈时忘记把循环起点从写死的 `0` 改成当前边界值。

> ⚠️ 搜索二维矩阵 II：`while` 边界条件容易多减 1（如写成 `i < matrix.length-1`），导致最后一行/第一列被排除在循环之外，本质是把「判断这一轮该不该执行」和「预判 ++/-- 之后会不会越界」搞混了。

> ⚠️ 矩阵置零（73）：`fill(0)` 的理解卡壳——rowArr/colArr 是**标记数组**不是矩阵数据，fill(0) 的含义是"全员初始无罪"，不是"把矩阵行列填成 0"；两个概念分清后写法就顺了。

> ⚠️ 矩阵置零重写事故三连：① 行列搞反（`matrix.length` 是行数不是列数）；② `matrix[i] = matrix[j] = 1` 把判决直接写进矩阵本体，破坏行结构（实测变成 `[[0,0,0],1,[0,0,0]]`）——判决只能写进标记数组；③ 第二遍条件写反 `colArr[i] == 0`（应为 `colArr[j] == 1`：行用 i、列用 j、标记为 1 才置零）。

### 核心知识点

- **链表本质是一组通过指针（`next`）串联的节点**，没有下标访问，只能从头开始顺着 `next` 走，所以链表题的核心动作永远是「移动指针」和「改变指针指向」。

- **双指针（快慢指针）**：一个指针走一步，另一个走两步（或有固定间隔），常用于判断链表是否有环、找中点、找倒数第 N 个节点等。

- **虚拟头节点（dummy node）**：在头节点本身可能被删除/改变的场景（如删除节点、合并链表、两两交换），提前创建一个 `dummy.next = head` 的哨兵节点，可以避免对「头节点是否要特殊处理」写额外的 if 分支，统一逻辑。

- **反转链表**是链表题里最基础也是复用率最高的操作，很多题（回文链表、K个一组翻转等）内部都会用到「反转某一段链表」这个子过程。

- **递归 vs 迭代**：链表天然具有递归结构（每个节点的 `next` 又是一个子链表），很多链表题既可以用迭代（循环+指针）解，也可以用递归解，需要能看懂两种写法并权衡空间复杂度（递归有调用栈开销）。

### 通用技巧

| 技巧 | 说明 |
| --- | --- |
| 画图模拟 | 链表题极度依赖「画箭头图」来跟踪指针变化，尤其是反转、交换类操作，强烈建议每写一步就画一下当前的指针指向，口算容易出错。 |
| Dummy Node | 只要涉及「头节点可能被删除或改变」的操作，第一反应就设置 `dummy`，用 `dummy.next` 最后返回真正的头节点。 |
| 快慢指针 | 找中点：慢指针走1步、快指针走2步，快指针到末尾时慢指针恰好在中点。判环：快慢指针从同一起点出发，若有环必相遇；找环入口需要额外的数学推导（第二次相遇点）。 |
| 先保存 next 再断开 | 反转/交换指针指向前，一定要先用临时变量保存原来的 `next`，否则改指针后会丢失后续链表的引用，导致链表「断掉」。 |
| 边界情况检查清单 | 空链表、只有一个节点、只有两个节点——链表题几乎都要过一遍这三种边界，很容易漏掉。 |

### 本专题踩过的坑

> ⚠️ **反复出现的高频错误**：`=`（赋值）和 `==`/`!==`（比较）混用，比如 `while(fast=slow)` 导致死循环、`ListNodeB==null` 误写成 `ListNodeB=null`；循环条件方向写反（如把「继续循环」的条件误写成「该停止」的条件，如 `while(left!==right)` 用在起点必然相等的场景，会导致循环一次都不执行）。

> ⚠️ 相交链表：双指针到达自己链表末尾后，误跳转到「此刻对方指针所在的位置」而不是「对方链表最初的头节点」，需要额外用不会变化的 `headA`/`headB`（函数参数本身，从未被重新赋值）作跳转目标。

> ⚠️ 反转链表：`let prev = curr.next; curr = prev` 这种「先改 curr 再赋值给 prev」的顺序错误，导致 prev 和 curr 指向同一节点；四步操作（存 next → 改指针 → 挪 prev → 挪 curr）顺序不能打乱。

> ⚠️ 回文链表（进阶）：快慢指针找中点的循环条件用「移动前检查」（`fast!==null && fast.next!==null`）而非「移动后检查」（`fast.next!==null && fast.next.next!==null`），对长度为2这类边界链表会导致 slow 多走一步，反转部分变空，比较循环被整个跳过、永远返回 true。

> ⚠️ 环形链表：起点必然相等，不能把「是否相遇」直接写进 `while()` 括号里判断（会在第一轮就被挡住不执行），需要用 `while(true)` + 内部 `if` 的结构，把「移动」和「判断相遇」拆开、保证移动发生在判断之前。

> ⚠️ 创建 dummy 节点时参数顺序搞反：`new ListNode(head, n)`（应为 `new ListNode(0, head)`），构造函数是 `ListNode(val, next)`，第一个位置永远对应 val，第二个位置永远对应 next，与传入的实参类型无关，只看位置。

> ⚠️ `let a, b, c = 1` 这种写法只有最后一个变量被真正赋值，前面的都是 `undefined`，JS 不支持类似 Python 的连续赋值语法。

> ⚠️ 两两交换节点：直接写 `root.left = root.right` 再写 `root.right = root.left` 会导致第一行赋值后原始信息被覆盖，第二行用到的已经不是「原始」的值——和交换两个变量的经典陷阱同理，必须先用独立的临时变量分别存好两个「源」，再各自赋值回去，顺序才不会互相干扰。

> ⚠️ 138 随机链表的复制：涉及「先建立映射再接指针」的两遍遍历模式，较绕，暂缓，后续找时间单独回顾。

### 核心知识点

- **三种DFS遍历顺序**：前序（根→左→右）、中序（左→根→右，对BST而言结果天然升序）、后序（左→右→根）。

- **递归解树类题目的核心三要素**：①明确函数定义（传入一个节点，要返回什么）②想清楚当前节点的答案如何由左右子树的答案推导/合并出来 ③想清楚终止条件（空节点该返回什么）。

- **「合并子树结果」型 vs 「交换/改写」型**：像求深度、求直径这类题，是把左右子树各自的答案合并成当前节点的答案；翻转二叉树这类题，则是把递归处理好的左右子树直接交换位置挂回去，两种模式的代码结构相似但目的不同。

- **一次遍历顺便维护全局最优解**（如543题）：递归函数本身返回的是"深度"这类中间结果，但过程中可以顺便用一个声明在函数外部的变量，记录"经过当前节点的答案"并不断取最大值，这是"递归返回值"与"最终要的答案"不是同一件事时的常见处理方式。

- **判断"镜像对称"需要双参数递归**（101题）：单参数的遍历只能站在一个节点上，无法同时掌握"另一侧对应位置走到哪了"，必须设计一个接收两个节点的辅助函数，且是"交叉"传参（左的左 配 右的右，左的右 配 右的左）。

- **验证BST需要传递上下界，不能只比较直接父子**（98题）：BST要求整棵左子树 < 根 < 整棵右子树，不是只看直接孩子，需要用 (min, max) 区间一路向下收紧传递。

- **层序遍历（BFS）用队列，不是递归**（102题）：是本专题里唯一不是纯递归的题型，需要 `while(queue.length>0)` 外层 + 内层固定次数循环，逐层剥离处理。

### 递归模式总结（同一套四步法，"当前节点该做什么"这一步分七种情况）

| 模式 | 核心特征 / 例题 |
| --- | --- |
| 单纯遍历型 | 递归只负责"走一遍"，边走边收集结果，不需要合并左右子树的答案。例：94中序遍历、230第K小 |
| 合并左右结果型 | 递归返回值本身就是答案的一部分，当前节点答案=左右子树答案的某种运算。例：104最大深度（取较大+1）、543直径（相加，顺便用全局变量记录最优解） |
| 交换/改写型 | 不是"算出一个值"，而是直接修改树结构本身。例：226翻转二叉树、114展开为链表 |
| 双参数比较型 | 单参数递归没法同时掌握"两个位置"的信息，需要设计成接收两个节点、成对同步递归。例：101对称二叉树（交叉比较左的左vs右的右） |
| 携带约束条件下传型 | 除节点本身，还要往下传一个"限制条件"（上下界、数组区间下标等），每层根据当前节点收紧限制。例：98验证BST（传min/max）、105前序中序构造（传数组区间） |
| 双重递归型 | 外层递归负责"枚举所有可能的起点"，内层递归负责"从固定起点出发计算"。例：437路径总和III |
| 回溯判断型 | 先递归深入到底拿到左右子树各自结果，再根据结果组合情况反向判断当前节点该扮演什么角色。例：236最近公共祖先（left&&right同时非空→当前节点是答案） |

| 层序遍历的层数分离 | 进入内层循环前必须先把 `queue.length` 存进一个独立变量（如 `currLength`），因为这个数字之后不会再变化，循环体内不断有新节点被 push 进 queue 也不受影响；如果直接拿 `queue.length` 做循环判断条件，会被新数据污染，导致层与层混在一起。 |

### 本专题踩过的坑

> ⚠️ 递归函数忘记加终止条件（`if(!node) return ...`），导致对 null 取属性直接报错——这是几乎每道树递归题第一次尝试都会漏掉的一步。

> ⚠️ 递归函数内部误用外层固定不变的 `root`，而不是当前层真正的参数（如 `node`），导致递归无法真正逐层深入，每层都在处理同一个顶层节点。

> ⚠️ 把自己写的递归函数（如 `maxDepth`）和 JS 内置的 `Math.max` 搞混，直接把两个数字传给自定义的递归函数求"最大值"，而不是调用 `Math.max()`。

> ⚠️ 求最大深度/直径时忘记 `+1`（当前节点自己也占一层），或者搞混"节点自身深度需要+1"与"经过该节点的路径长度不需要+1"这两个不同的量。

> ⚠️ 对称二叉树：一开始设计成单参数遍历函数，用 `root.left !== root.right` 直接比较两个不同的节点对象（永远为 true，因为比较的是引用地址），未能建立"双参数交叉比较"的正确模型。

> ⚠️ 全局累加变量（如 `maxD`/`maxDiameter`）忘记在函数外先用 `let` 声明，直接使用导致 `undefined` 参与运算变成 `NaN`。

> ⚠️ 层序遍历：`for` 循环条件写成 `i < levelSize.length`（levelSize 是数字，没有 .length 属性，结果恒为 undefined，循环条件恒为 false，内层不执行但外层死循环）；以及用 `pop()` 代替 `shift()` 破坏先进先出顺序；花括号未正确闭合导致 `return` 提前写进了循环体内，只处理第一层就退出；`queue=[root]` 对空树（root为null）时数组长度仍是1，必须显式 `if(!root) return []`，不能依赖队列长度自动判断空树。

> ⚠️ 验证BST：忘记递归调用中第二个参数应始终是 `node.val`（不是 `left.val`/`right.val`，因为left/right本身就是数字没有.val属性）；右子树递归时误传 `node` 自己而不是 `node.right`，导致递归无法真正深入；判断条件用 `<`/`>`漏掉等于边界，应为 `<=`/`>=`（BST不允许重复值）。

> ⚠️ 右视图：push孩子节点时误写成 `queue.push(node.val)`（push进去的是值不是节点），下一轮shift出来的是数字而非对象，取 `.val`/.left/.right 时报错或得到undefined。

> ⚠️ 从前序中序构造二叉树：`slice` 切割左子树部分的终点边界容易搞错（`preorder.slice(1,mid+1)`，mid既代表"根在中序里的下标"又被借用为"左子树节点数量"，两个数组里含义不同但数值相同，容易理解成"取到根节点"而误以为重复）；空数组判断误写成 `!preorder`（空数组是真值，不在falsy清单里），必须用 `preorder.length===0`，否则递归永远不会停止导致栈溢出；方法名大小写拼错（`indexOf`误写成`IndexOf`）。

> ⚠️ 路径总和III：内层dfs忘记终止条件（对null取.val报错）；`remain-root`应为`remain-root.val`；内层dfs末尾误写`return root`应为`return count`；外层递归误用`dfs(root.left,...)`而非`pathSum(root.left,...)`，导致只对根的直接孩子重新算了一次以其为起点的路径，却没有让这些孩子自己的子节点也被当作全新起点枚举到，会漏算路径（需要outer函数完整递归自己，而不是只调用内层dfs一次）。

> ⚠️ 最近公共祖先：容易把"终止条件"（root是null/p/q时返回）误认为是"找到答案的核心逻辑"，实际上真正判断LCA的是 `if(left&&right)return root` 这一行——终止条件只负责"何时停止递归网上报告"，核心推理发生在回溯汇总的那一层；`return root` 里的root是当前递归层自己的root（每层参数各自独立，同名不冲突），不是最外层传入的root。

### 核心知识点（回溯部分）

- **回溯的本质是"做选择 → 递归 → 撤销选择"这一套通用骨架**，靠系统性地穷举所有可能的路径来找到全部答案；"撤销"这一步是为了保证某一条分支尝试过的东西，不会污染到它的兄弟分支。

- **两种主流写法，逻辑等价，区别只在"要不要手动撤销"**：一种是**原地修改共享数组**（`path.push(x); dfs(path); path.pop()`，46/39/17/131的start-i写法都是这个模式），必须手动 `pop` 配对撤销；另一种是**每次用展开运算符新建数组**（`dfs([...path, x], ...)`，78的选/不选写法、131的选/不选写法），不碰原数组，天然不需要撤销。

- **结果收集的两种时机**：只在"选够/选满"的叶子节点收集一次（46排列、17电话号码、22括号生成、39组合总和、131分割回文串——这几题的合法结果都要求"长度/总和恰好达标"）；**每个节点都收集**（78子集——因为任意长度的组合本身就是一个合法子集，不需要等到某个特定终点）。

- **剪枝的本质是"提前判断，不合法的分支根本不调用 dfs"**，具体判断依据因题而异：78用"有没有用过"（`includes`）、22用"左右括号数量的大小关系"、39用"当前和有没有超过目标值"、131用"切出来的子串是不是回文"（调用一个外部判断函数）。

- **递归传参是 `i` 还是 `i+1`，取决于"这一步选完之后，同一个候选还能不能再选一次"**：39组合总和允许同一个数字重复使用，所以传 `i`；78子集、131分割回文串每个位置只能用一次，所以传 `i+1`。

- **连续的多个 `if` 不是 `if/else`**：像78、131的"选/不选"写法里，两个 `if` 各自独立判断、条件成立就会执行，不存在"满足了第一个就跳过第二个"。第一个 `if` 里的 `dfs` 调用会完整探索完自己那整条分支（可能产生好几个结果）才会返回，程序才会往下走到第二个 `if`。

- **母题识别**：78子集的"`start` 控制起点、只往后选不回头"是这几道题共享的底层结构；46排列因为要考虑顺序（可以选任意还没用过的数），换成了"查重"而不是 `start`。一句话概括——**"能不能往回选"决定了骨架用查重还是用 `start`**。

| 题目 | 候选集合怎么来 | 终止条件 / 收集时机 | 剪枝 / 合法性判断 | 特殊点 |
| --- | --- | --- | --- | --- |
| 46 全排列 | 遍历整个 nums，靠查重挑没用过的 | path.length===nums.length（叶子收集） | `arr.includes(num)` | 递归传的是同一个 arr，push/pop 必须配对撤销 |
| 78 子集 | `start` 控制起点，不回头 | 每个节点都收集，不需要专门判断 | 无需剪枝，任意子集都合法 | for循环版传 `i+1`；选/不选版是两个独立 if，不是 if/else |
| 17 电话号码 | 当前数字 `digits[index]` 对应的字母表 | index===digits.length（叶子收集） | 无（每一位必须选一个，不存在不合法分支） | 用字符串拼接 `str+item` 代替数组 push |
| 22 括号生成 | 只有 `'('` 和 `')'` 两种候选 | path.length===2n（叶子收集） | `left<n`（还能加左括号）/ `right<left`（右括号不能超过左括号） | 剪枝条件可以用"已用数量"或"剩余数量"两种等价视角改写 |
| 39 组合总和 | `start` 控制起点，但允许重复选同一个数字 | sum===target（叶子收集），sum>target 提前剪枝 | sum 超过 target 就直接 return | 递归传的是 `i` 不是 `i+1`（允许复用同一个数） |
| 131 分割回文串 | `start` 切到哪个 `i`；或"选/不选"逐字符往后挪 | start（或i）===len（叶子收集） | 切出来的子串必须是回文（`is()` 双指针判断） | 切完之后新窗口的 start 和 i 都设为 `i+1`，因为新窗口最初只有一个字符，起点和当前位置天然重合 |

### 通用技巧

| 技巧 | 说明 |
| --- | --- |
| 先问"骨架见过吗" | 拿到新的回溯题，先套用户自创的"母题+变体"方法：判断这题跟哪道见过的题骨架一致，只想清楚新题在哪个"插槽"（候选集合/终止条件/剪枝方式/传参）里改了逻辑，不需要每次从零搭骨架。 |
| 递归调用栈的直觉 | `dfs(...)` 这一行不是"调用完立刻继续下一行"，而是"整个跳进去，把这条分支能展开的所有可能都探索完"，中间可能还要再递归好几层，这一步没走完，外面的代码（比如 `pop()` 或下一个 `if`）都不会执行。 |
| 逗号的两种身份 | 函数调用括号 `()` 里的逗号永远是"参数分隔符"；数组字面量 `[]` 里的逗号永远是"元素分隔符"。两种逗号叠在一起用（如 `dfs([...arr,nums[index]],index+1)`）容易看串，要先按括号层级拆开再读。 |
| substring/slice 左闭右开 | `s.substring(start, i+1)` / `s.slice(start, i+1)` 都是"取到第二个参数之前"，所以要写 `i+1` 才能真正取到下标 `i` 这个字符本身；容易漏写 `s.` 前缀导致报错。 |

### 本专题踩过的坑

> ⚠️ 把该往 `arr` 里加的操作写成往 `ans` 里加（`ans.push(arr)` 而不是 `arr.push(num)`），导致 `arr` 永远是空数组、终止条件永远不成立，最终无限递归栈溢出（`Maximum call stack size exceeded`）。

> ⚠️ 变量名对不上号：定义的数组叫 `ans`，最后却 `return res`（`res` 从未定义）；类似的还有函数体内用了一个参数列表里根本不存在的变量（比如把 `right` 误写成 `i`）。

> ⚠️ 边界条件里 `ans.push(path)` 后漏写 `return`，代码会继续往下掉进 `for` 循环，此时下标已经越界，取值拿到 `undefined`，对 `undefined` 做 `for...of` 遍历直接报错。

> ⚠️ "选"和"不选"两行递归调用，**唯一相同的地方（`index+1`）反而最容易漏**：`dfs(arr,index)` 少加了 `+1`，导致"不选"分支永远在检查同一个位置，递归到不了终止条件，无限递归栈溢出。

> ⚠️ 共享数组污染：直接对同一个 `path`/`arr` 做 `push` 却没有配对的 `pop` 撤销（或者手误多 `push` 了一次），导致"选"和"不选"两条分支用的是同一个被污染过的数组，互相影响。

> ⚠️ 剪枝条件里拿一个固定值和一个变化的量比较（如 `if(right<n)`），而不是两个"同类型、都在变化"的量互相比较（应为 `right<left`）——某些测试用例可能侥幸通过，但剪枝逻辑本身是错的，起不到真正的作用。

> ⚠️ "剩余数量"和"已用数量"两种记账视角混用：变量定义成"剩余可用数量"（从 `n` 往下减），初始调用却还是传 `0,0`（应为 `n,n`），或者判断条件用了"已用"视角该有的写法。

> ⚠️ 运算符优先级陷阱：`!s[left]==s[right]` 里 `!` 的优先级比 `==` 高，实际执行的是 `(!s[left])==s[right]`，根本不是"判断两个字符不相等"，应写成 `s[left]!==s[right]`。

> ⚠️ 双指针函数忘记移动指针：`while` 循环体内只判断条件、没有 `left++`/`right--`，导致死循环。

> ⚠️ 混淆"多个独立的 `if`"和"`if/else`"：连续的 `if` 语句是各自独立判断、条件成立就会执行，不是"满足了第一个就跳过第二个"——第一个 `if` 里的 `dfs` 会完整探索完自己那条分支（可能产生好几个结果）才返回，程序才会往下走到第二个 `if`。

> ⚠️ 切割类问题里，一刀切下去之后，新窗口的 `start` 和当前位置为什么都设成 `i+1`：因为新窗口在还没扩展之前，天然只包含一个字符——"新窗口的起点"和"当前检查到的位置"此刻就是同一个下标，之后如果继续"不选"，两者才会拉开距离。
